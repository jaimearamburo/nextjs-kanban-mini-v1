# Real-time events are invalidation signals, not data

After a successful change commits, the Server Action calls `updateTag` and publishes a small "Task X changed" event on an Ably Board channel. Other browsers respond by calling `startTransition(() => router.refresh())`, a soft refresh that keeps client and scroll state and shows no Suspense fallbacks. Events carry no data, so the server stays the only source of truth and there is no second client-side model to keep in sync. Clients skip events their own actions caused, combine bursts into one refresh, and wait until a drag ends before refreshing. Patching client state directly from event payloads was rejected because it duplicates the read model. Server-side `refresh()` was rejected because it can only reach the browser that called the action.
